## Уточнения из рабочей сессии

- Launcher: EXE с локальным HTML/CSS-интерфейсом внутри минибраузера, не прежние
  Win32 controls. Portable по наличию любого `portable.txt` рядом с launcher:
  профили/конфиги/saves/cache/logs в `user/` рядом с ним; перенос из AppData с
  подтверждением, без перезаписи существующих данных.
- Оформление launcher — по `refs/ANOM_Style`, **только стиль, не его вёрстка**;
  добавить переключение светлой/тёмной темы с сохранением выбора.

- После мастер-сервера добавить server list в launcher и возможность выбрать
  IP/домен мастер-сервера (не только фиксированный встроенный адрес).

- Обычный выход одного игрока не должен завершать мир у напарника: оставшийся
  продолжает кооп-карту один. Выходящий F7 — в меню; survivor сохраняет world/
  inventory/rules, но reconnect/late join/dedicated server этим не подразумеваются.

- Новые идеи/план: удобный launcher, server browser/master; in-game voice chat;
  общий и командный чат для будущих TDM/командных режимов; настройки игрока,
  цветные ники/цвет персонажа, cosmetic skins (humanoid зомби/имп и т.п.).
- Дальнейшая графика: Vulkan, 3D floors, HD texture/sprite replacements, voxels.
  Полный список с границами и предложениями ассистента — `docs/IDEAS.md`.
- Сообщён баг: T вызывает вылет (стандартный общий чат). Реестр/причины/статус:
  `docs/BUGS.md`; не скрывать проблему отключением чата.

- Идеи для МП (подробно `docs/IDEAS.md`): сервер с configurable max до 1024,
  DM-боты и COOP-боты, способные проходить игру (ключи/кнопки/двери/бой/выходы).
  Это долгосрочные цели, не текущая двухпользовательская сеть.
- Нужны dmflags: скрыть multiplayer-only оружие в COOP; block/pass столкновений
  игроков. Будущий server config auto включает pass при configured maxplayers >4,
  явные block/pass должны переопределять auto.

- В GitHub Actions публиковать downloadable build artifacts для друзей и других
  тестировщиков до появления релизов. Включать runtime-зависимости и инструкции,
  commit ID/лицензии/соответствующие исходники; не включать IWAD и user data.

- Разрешить сохранять момент attract-demo через меню/F2, а затем загружать его
  как одиночную игру с управлением игрока (в духе старого BUILD-прикола).
- После реализации сети: разрешить локальный snapshot онлайн-игры; при загрузке
  из МП предупредить, что это отключит от сервера, и запросить подтверждение.
  Загрузка идёт в single-player, не откатывает сервер/других игроков.

- Лицензионный Doom II для локальных тестов лежит в `refs/iwads/doom2.wad`;
  не включать его в Git/дистрибутив.
- Нужен headless для частых автоматических тестов. Он добавлен отдельным
  бэкендом; команды описаны в `docs/TESTING.md`.
- После средних/крупных изменений иногда запускать обычное окно игры для
  демонстрации владельцу, но не после каждой мелкой правки.
