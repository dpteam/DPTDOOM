# Идеи и цели владельца

Это список требований/направлений, **не список уже работающих возможностей**.
Текущая сеть — экспериментальный direct TCP lockstep ровно на двух игроков.

## Большие серверы: до 1024 игроков

- Цель/план: настраиваемый максимум до **1024 игроков** на сервере.
- Владелец привёл Odamex как ориентир качества и упомянул массовые сессии около
  300 игроков. Это его ориентир, а не проверенный здесь benchmark или заявление
  DPT.DOOM об историческом рекорде.
- Не решается заменой `MAXPLAYERS`: нужны authoritative dedicated server,
  другая модель репликации/interest management, stable object/player IDs,
  bandwidth/CPU budgets, prediction/interpolation, динамические массивы,
  новые save/demo/protocol форматы и нагрузочное тестирование.
- Промежуточные проверяемые этапы: 4 → 8/16 → 32/64 → дальше по измерениям.
  Сотни/1024 — только после реальных профилей и стабильных длительных сессий.
- Двухпользовательский TCP-прототип не считать архитектурой готового 1024-player server.

## Боты DM и COOP

- DM: навигация, поиск оружия/боеприпасов/здоровья, бой, выбор цели и маршрута,
  respawn, уровни сложности, ограничения нечестного знания карты/противников.
- COOP: уметь **проходить игру**, не только следовать/стрелять: ключи, двери,
  кнопки/лифты/телепорты, обязательные триггеры, секреты по политике, выход с карты,
  бой с монстрами и сотрудничество с людьми/другими ботами.
- Нужны navigation graph/mesh и моделирование механик/зависимостей целей,
  восстановление после застревания, тестовые карты/сценарии и replay тесты.
- Scripted headless input в тестах — **не боты**. Нельзя выдавать его за AI.
- Сначала ограниченный DM navigation/combat, затем COOP puzzle progression;
  совместимость с нестандартными WAD/DECORATE потребует дополнительных правил.

## DMFLAGS / правила матча

Минимальное подмножество уже реализовано: `-dmflags 1`/`2`/`3`, описание и
проверки в `docs/NETWORK.md`. Server config/auto/maxplayers остаются идеями.

- Настраиваемые и сверяемые правила независимо от названия режима, чтобы
  менять COOP/DM поведение явно, а не случайными legacy hacks.
- COOP: возможность убрать multiplayer-only оружие, не убирая обычные оружия
  и дополнительных кооп-монстров. В vanilla THINGS флаг 16 общий multiplayer,
  отдельного deathmatch-only бита в этом формате нет.
- Игроки: block/unblock прохождения друг сквозь друга. Это не `noclip` мира,
  не невидимость и не отключение урона/выстрелов между игроками.
- Для будущего серверного config: collision policy `auto|block|pass`.
  В `auto` разрешать прохождение, если **configured maxplayers > 4**, не по
  текущему числу подключённых. Явные `block/pass` должны переопределять auto.
- Сейчас maxplayers фиксирован на 2 и server config отсутствует: auto не
  изображать работающей настройкой, не вводить неиспользуемый `maxplayers`.
- Изменение правил при сохранениях/демо должно быть отражено в новых форматах;
  не ломать vanilla DSG или демо неявными локальными flags.
