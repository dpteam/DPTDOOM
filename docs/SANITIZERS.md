# AddressSanitizer и границы проверки

## Windows x64 / MSVC

Нужны Visual Studio 2022 C++ и установленный компонент MSVC AddressSanitizer.

```powershell
cmake --preset windows-asan -DDPTDOOM_TEST_IWAD="$PWD/refs/iwads/doom2.wad"
cmake --build --preset windows-asan
& ./build/windows-asan/RelWithDebInfo/dptdoom-headless.exe --version
ctest --preset windows-asan
```

Это **headless RelWithDebInfo**, не основной Release. LTO отключён, добавлены
символы, ASan-инструментация и запрет incremental linking. DLL
`clang_rt.asan_dynamic-x86_64.dll` автоматически копируется из каталога выбранного
MSVC compiler рядом с EXE и тестами. Если runtime не найден, configure должен
завершиться ошибкой, а не оставлять EXE без DLL. Сначала проверять `--version`;
не запускать десятки тестов, если Windows сообщает отсутствующий runtime.

`ASAN_OPTIONS=halt_on_error=1:detect_leaks=0` задан в test preset. MSVC ASan здесь
не используется как LeakSanitizer. Нулевое число находок не означает отсутствие
утечек или всех возможных ошибок памяти.

## Собственный zone allocator

Обычно ASan видит память Doom как один большой `malloc`. При `DPTDOOM_ASAN`
`z_zone.c` дополнительно poison-ит освобождённую payload-память и хвост за
запрошенным размером. Метаданные остаются доступны для coalescing; при reuse
блок unpoison-ится. В обычной сборке ASan API не используется, поведение
аллокатора и размеры запрашиваемых объектов сохраняются.

`zone-memory` проверяет allocation/free/reuse, owners и освобождение по тегам.
`asan-zone-uaf` и `asan-zone-overflow` намеренно запускают ошибочные обращения
в **дочернем тестовом процессе** и считаются успешными только при настоящем
отчёте ASan с указанием тестового исходника. Они не являются скрытыми ошибками
игры. У проверки есть ограничения: живые metadata и поглощённые заголовки не
полностью покрыты redzones; это не замена построчному аудиту.

## Что найдено и исправлено

- `R_RenderSegLoop`: индекс таблицы тангенсов выходил за её половину окружности
  в DEMO3 Doom II. Теперь индекс оборачивается по периоду тангенса (180°).
- PNAMES: фиксированное 8-байтовое имя передавалось как C-string, функция проверки
  усечения читала девятый байт. Теперь ровно 8 байт + собственный NUL.
- Masked sprite posts: округление координат могло читать байты вне длины post.
  Для постов sample index ограничен длиной, wall/sky сохраняют прежний wrap.
- Thinker deletion: `next` читался после `Z_Free`; теперь сохраняется до free.
- Death camera/HUD: последний атакующий missile мог быть удалён до чтения
  координат. Теперь остаётся coordinate-only запись, не указатель в мёртвую зону.
- Windows error message: размер wide-буфера передавался в байтах вместо wchar.
- Timer: умножение миллисекунд на 35 выполняется в 64 битах; исправлена нулевая
  начальная отметка. Синтетические тесты проверяют длительное время и wrap
  платформенного 32-битного счётчика. Полный горизонт счётчика остаётся 2^32 ms.

Игровые потиковые эталоны **не изменены**. Исправления рендера могут менять
отдельные пиксели там, где раньше читалась посторонняя память; побитовая
идентичность всех кадров DOS Doom не заявляется.

## Другие конфигурации

`DPTDOOM_SANITIZER=none|address|undefined` — CMake-настройка. MSVC поддерживается
здесь только с `address`, x64. Для GCC/Clang проверяется возможность компиляции
и линковки runtime; при её отсутствии configure падает явно. UBSan и санитайзеры
на Linux/macOS в этой сессии **не проверены**. Legacy fixed-point код содержит
signed shifts/overflow conventions, их нельзя молча подавлять или менять ради
зелёного отчёта. Набор 64-битных предупреждений MSVC ещё не полностью разобран.

## Набор сценариев

Проверены: три встроенных демо Doom II, save/load и повреждённые DSG, headless
capture/ошибки аргументов, allocator probes и timer tests. Дополнительно ASan
прогнал три демо и save/load shareware v1.8. Это не fuzzing произвольных модов
и не проверка всех карт. Автотесты не требуют видимых окон.
